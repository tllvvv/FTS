# Сравнение методов индексирования текстовых данных в PostgreSQL

Программная часть учебной практики «Современные методы индексирования для работы
с текстовыми данными в PostgreSQL».

Репозиторий содержит полный набор сценариев, воспроизводящих эксперимент:
подготовку корпуса, построение векторных представлений, загрузку базы данных,
серию измерений и построение таблиц и графиков для отчёта.

## Что сравнивается

|Семейство|Индекс|Расширение|Тип запросов|
|-|-|-|-|
|Полнотекстовый|GIN по `to_tsvector`|ядро|слово, конъюнкция, фраза, топ-*k* по `ts_rank`|
|Полнотекстовый|GiST по `to_tsvector`|ядро|то же|
|Полнотекстовый|RUM по `to_tsvector`|`rum` 1.4|то же + топ-*k* по оператору `<=>`|
|Триграммный|GIN `gin_trgm_ops`|`pg_trgm` 1.6|`LIKE '%...%'`, словное сходство|
|Триграммный|GiST `gist_trgm_ops`|`pg_trgm` 1.6|то же + топ-*k* по расстоянию|
|Векторный|HNSW|`pgvector` 0.8.6|kNN, `ORDER BY emb <=> q LIMIT 10`|
|Векторный|IVFFlat|`pgvector` 0.8.6|то же|

Дополнительно измеряется базовый вариант без индекса и вариант
GIN с `fastupdate = off` (только в эксперименте со вставкой).

## Измеряемые показатели

* время построения индекса (`CREATE INDEX`);
* размер индекса на диске (`pg_relation_size`);
* время выполнения поисковых запросов (5 повторений после прогрева);
* время вставки 1 000 строк в проиндексированную таблицу;
* полнота выдачи `recall@10` для приближённых векторных индексов.

Объёмы выборок: 300, 30 000 и 300 000 статей.

## Порядок запуска

```bash
pip install -r requirements.txt

# Скачать датасет DBPedia Classes в data/raw/
#    (DBPEDIA_train.csv, DBPEDIA_val.csv, DBPEDIA_test.csv)

python scripts/01_prepare_data.py      # формирование корпуса и выборок
python scripts/02_embeddings.py        # векторные представления (ONNX, CPU)
python scripts/03_load_db.py --force   # создание БД ftsbench и загрузка таблиц
python scripts/04_pick_queries.py      # выбор поисковых запросов по частотам
python scripts/05_run_experiments.py   # измерения
```

## Структура репозитория

```
scripts/      сценарии эксперимента (нумерация задаёт порядок запуска)
sql/          SQL-код: схема, определения индексов, тексты запросов
data/prepared/корпус, эмбеддинги, эталонные ответы kNN
results/      сырые измерения, агрегаты, планы выполнения
```

## Формат результатов

`results/raw_measurements.csv` — одна строка на одно измерение:

|поле|описание|
|-|-|
|`experiment`|`build` / `size` / `search` / `insert`|
|`table`, `rows`|таблица и её объём|
|`index`|метод индексирования либо `none`|
|`query`|идентификатор запроса|
|`param`|параметр поиска (`hnsw.ef_search`, `ivfflat.probes`)|
|`run`|номер повторения|
|`seconds`|время выполнения|
|`result_rows`|размер результата|
|`extra`|размер индекса, `recall@10` либо типы узлов плана|
